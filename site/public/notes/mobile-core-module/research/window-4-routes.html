Окно 4 · Routes

Точки входа, к которым пользователя может привести приложение. Модуль-издатель объявляет событие (с префиксом своего имени), app.ts маппит его в URI, модуль-владелец объявляет точку входа.

Из профиля — в чат поддержки

Издатель события: модуль profile (нейминг — profile/<event> согласно events.md §4.1). Маппинг: connections в app.ts. Владелец экрана: модуль support.
шаг 1 · событие
profile · объявляет ProfileSupportEvent
Нейминг: profile/support — сразу видно, что событие из модуля profile.
import { makeEvent } from '@core'; export namespace ProfileSupportEvent { export interface Context { reason: string; } } export const ProfileSupportEvent = makeEvent<ProfileSupportEvent.Context>('profile/support');
шаг 2 · публикация
profile · в нужном месте
Где: обычно в model/store.ts или в обработчике клика.
EventBus.publish(ProfileSupportEvent, { reason: 'help-with-order' });
profile/support
→
/support/chat
шаг 3 · connection
app.ts · маппит событие в URI
import { ProfileSupportEvent } from '@superapp-mobile-core/application-module-profile'; init([..., profile, support], { connections: { [ProfileSupportEvent.value]: '/support/chat', }, });
шаг 4 · точка входа
support · объявляет inlets и inject
Нейминг inlets: те же URI, что в connections.
export default makeModule<Support.Defaults>('support', (inject) => { inject('/support/chat', () => (<SupportChat />)); return { navigation: { inlets: ['/support/chat'] }, }; });
Что делает ядро: при EventBus.publish(ProfileSupportEvent, …) находит connection profile/support → /support/chat, открывает контейнер SupportChat и кладёт reason в layer.props.
