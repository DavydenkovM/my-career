Окно 5 · Platform (контракт с BFF)

Сервис модуля расширяет Platform.Service. Каждый метод принимает request и опциональный metadata — через metadata модуль и BFF договариваются о поведении: allowStale, timeoutMs, ретраи.

profile наследует Platform.Service — частичный контракт живёт в metadata

Кто заявляет: модуль profile через Service extends Platform.Service. Кто исполняет: BFF через platform middleware. Частичность: метод uploadAvatar — optional, проверяется через metadata.
profile · services/Profile/index.ts
import { Platform } from '@core'; export class Profile implements Profile.Service { static makeService(defaults: Profile.Data) { ... } async getProfile( request: { id: string }, metadata?: Platform.Metadata, ): Promise<Profile.Data> { ... } async updateProfile( request: Profile.Data, metadata?: Platform.Metadata, ): Promise<void> { ... } async uploadAvatar( request: { id: string; uri: string }, metadata?: Platform.Metadata, ): Promise<{ url: string }> { ... } } export namespace Profile { export interface Service extends Platform.Service { getProfile: (r: { id: string }, m?: Platform.Metadata) => Promise<Data>; updateProfile: (r: Data, m?: Platform.Metadata) => Promise<void>; uploadAvatar: (r: { id: string; uri: string }, m?: Platform.Metadata) => Promise<{ url: string }>; } }
вызов с metadata — частичный контракт
const profile = Application.resolveSync<Profile.Service>('profile'); // обычный вызов const p = await profile.getProfile({ id: 'u-42' }); // с metadata: «можно вернуть кеш, иначе подождать 5s» const fresh = await profile.getProfile( { id: 'u-42' }, { allowStale: true, timeoutMs: 5_000 }, );
