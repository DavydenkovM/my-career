Публичный контракт

Три явных канала, через которые модуль Mobile Core общается с внешним миром — и как они решают проблемы FSD с коммуникацией, контрактами и переносимостью.

Модуль A

Например, form
Конфигурация
index.ts → makeModule(...)
Читает ядро
Декларация: service, navigation, locales, dependencies. Включение/выключение модуля.
Публичный контракт
events.ts
Импортируют другие модули
Типизированные события для навигации и реакций. Модуль A «просит» — другие модули «слышат».
Публичный API
services/ → Service
Запрашивают другие модули через Service Locator
Чтение/изменение данных модуля A извне. Никаких прямых импортов model/ или containers/.

Application Core

init([...]) + Service Locator + EventBus + Connections
// Точка входа в приложение init([formModule, containersModule], { defaults: { form: { ... } }, connections: { [FormConsequentScanEvent.value]: '#/containers/consequent-scan', }, themes: [MainTheme], });
// Резолв сервиса другого модуля const containers = Application.resolveSync<Containers.Service>('containers');
// Подписка на событие EventBus.subscribe(AuthenticationLossEvent, onAuthLoss);
// Глобальная навигация Application.go('/containers/select-bag', params);

Модуль B

Например, containers
Реакция на чужое событие
EventBus.subscribe(...)
Модуль B слушает события модуля A
Слабосвязанная коммуникация: модуль B не знает, кто именно публикует событие, и не зависит от URI модуля A.
navigation.routes
inject('/containers/...')
Ядро мапит event → URI через connections
Модуль A просит «перейди в containers» — ядро знает, какой URI у модуля B в текущей сборке.
Service Locator
Application.resolveSync
Модуль B запрашивает сервис модуля A
Контрактный вызов. Если сервис не зарегистрирован — ошибка на старте, а не в рантайме фичи.

Сценарий 1 — Навигация

Модуль form хочет открыть экран из containers, не зная его URI.
form → EventBus.publish(FormConsequentScanEvent) → core → connections[event] → URI → containers рендерит экран

Сценарий 2 — Данные

courier-order хочет прочитать заказ из legacy, не импортируя его model.
courier-order → Application.resolveSync<Legacy.Service>('legacy') → legacy.findOrderIndex(...)

Сценарий 3 — Реакция на событие

courier-order хочет обновить заказ, когда в photo-uploader загрузили фото.
photo-uploader → EventBus.publish(PhotoUploadedEvent) → courier-order обновляет свой стор
Все три канала — типизированные. any запрещён в публичных контрактах.
