Анатомия модуля

Какие слои есть в одном функциональном модуле Mobile Core, какие из них обязательны, кто их читает и зачем они нужны.

Структура модуля

Один обязательный файл + слои по необходимости
authentication/ ├── index.ts ← точка входа, контракт с ядром ├── events.ts ← публичные события ├── interfaces.ts ← сигнатуры entrypoint-коллбэков ├── package.json ← манифест, peerDependencies ├── components/ │ └── code-input.tsx ├── containers/ │ ├── block.tsx │ ├── code.tsx │ ├── phone.tsx │ └── report.tsx ├── configuration/ │ └── index.ts ← тип Defaults ├── constants/ │ └── index.ts ├── model/ │ ├── store.ts │ ├── builder.ts │ ├── adapters.ts │ └── index.ts ├── services/ │ ├── index.ts ← Service интерфейс │ └── make-service.ts ├── middlewares/ │ └── refresh.ts ← только auth/platform └── assets/ └── locale/ ├── ru.json └── en.json

● Обязательные

Только index.ts и package.json. Без них модуль не загрузится в ядро.

○ По необходимости

Слой появляется, когда в модуле возникает соответствующая ответственность. Никаких пустых директорий «по умолчанию».

Что делает каждый слой

Почему этот слой существует и какую задачу решает
index.ts
Контракт с ядром. Регистрирует экраны, сервис, события, локали, зависимости. Включение/выключение модуля = его присутствие в init([...]).
package.json
Манифест. Имя, версия, peerDependencies. Делает модуль переносимым в смежный проект.
events.ts
Публичные контракты. Типизированные события для навигации и слабосвязанной коммуникации с другими модулями.
services/
Единственный публичный API. Другие модули читают/меняют данные модуля только через Service Locator.
interfaces.ts
Контракт entrypoint. Сигнатуры коллбэков из index.ts в контейнеры. Не импортирует типы из model/.
model/
Инкапсулированное состояние: сторы, builders, adapters. Никогда не импортируется снаружи модуля.
containers/
Экраны и порталы. Получают данные через props, наследуют *Callbacks из interfaces.ts.
components/
Локальные UI-блоки, которых нет в общем UIKit. Чистые компоненты, получают данные через props.
configuration/
Типизированные Defaults. Значения приходят из init(defaults) и Remote Config.
assets/locale/
Свои локали. ru.json / en.json. Ядро мерджит их автоматически.
constants/
Общие неизменяемые значения, используемые в нескольких местах модуля.
middlewares/
Обработчики транспортного конвейера (только в authentication и platform).
