Гипотеза A · время и стоимость

Модули сложно выключить

правок в 5 центральных файлах, чтобы убрать одну фичу
// 1. Глобальный enum маршрутов
export enum AppNavigation {
  AUDIO = 'Audio', // ← удалить
  AUDIO_PLAY = 'AudioPlay',
}
// 2. Глобальный роутер
<Stack.Screen name=AppNavigation.AUDIO /> // ×42 экрана
// 3. Глобальный стор
import { playerReducer } from 'features/player/player-control'
// 4. Persist-whitelist (строкой!)
whitelist: [..., 'player', ...]
// 5. Провайдер bottom-sheets — хардкод виджетов
Для бизнеса
A/B-тест фичи = ручной рефактор 5 файлов. White-label = копировать приложение целиком.
Для разработчика
Любая фича знает про глобальный enum и стор. Нет plugin-точки — есть «shared contract» наоборот.

Для бизнеса
Регресс в одной фиче валит другую. Стоимость слияния фич растёт нелинейно.
Для разработчика
Общение — через глобальный Redux и прямые импорты. Нет message-bus, DI, pub/sub — всё протекает.

Для бизнеса
Нельзя быстро собрать «второе приложение» из готовых фич. Time-to-market нового продукта не падает с ростом базы фич.
Для разработчика
«Фича» — это конвенция, а не модуль. 5 ручных правок на каждое перемещение.
Гипотеза D · контракты

Контракты модулей неочевидны

API течёт: одна фича экспортирует и reducer, и selector, и UI
// features/setting/toggle-vibration/index.ts
export { getVibrationIsEnabled } // selector
export { vibrationReducer } // reducer
export { ToggleVibration } // UI
// ↓ 5 файлов «договорились» импортировать
// getLanguage из language-picker как контракт:
// entities/feed/useFeeds.ts
// features/send-message-chat/useSendMessage.ts
// features/send-message-chat/useChatOnline.ts
// features/feed/feed-create-post/FeedCreatePost.tsx
// screens/audio/audio/AudioScreen.tsx
// тип маршрутов — буквально any:
export type NavigationStackLists<F = any> = { ... }
Для бизнеса
Onboarding в проект длиннее. Больше шанс регрессии при «безобидном» рефакторе.
Для разработчика
Контракт = «как все привыкли». Нет интерфейса, нет DI, нет fake-store для тестов фичи изолированно.
